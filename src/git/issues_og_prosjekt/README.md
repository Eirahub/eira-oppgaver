# Om oppgaven {.activity}

Eleven lager issues med «Ferdig når», bruker merkelapper og ansvar, samler
sakene på en prosjekttavle og lukker et issue med en pull request. Til slutt
gjør eleven en plan med brukerhistorier om til issues.

## Oppgaven passer til: {.check}

__Fag__: Programmering, informasjonsteknologi

__Anbefalte trinn__: 8. trinn til videregående

__Tema__: Issues, prosjekttavle, kanban, planlegging, samarbeid

__Tidsbruk__: 45 til 60 minutter, alene eller i par

## Kompetansemål {.challenge}

- [ ] __Informasjonsteknologi 2, Vg3__: velge og bruke relevante
  systemutviklingsmetoder og -verktøy for samarbeid med andre

## Forslag til vurderingskriterier {.challenge}

Repoet har minst tre issues med tydelig tittel og «Ferdig når», en
prosjekttavle, og minst ett issue som er lukket av en pull request. Eleven kan
forklare hvorfor det lønner seg å ha få saker i **In Progress**.

## Forutsetninger og utstyr {.challenge}

- [ ] __Forutsetninger__: [Del koden på GitHub](../del_pa_github/del_pa_github)
  og [Prøv en idé på en gren](../grener/grener). [Samarbeid med pull
  request](../samarbeid/samarbeid) er nyttig, men ikke nødvendig.

- [ ] __Utstyr__: PC med VS Code og Git, og en GitHub-konto.

## Fremgangsmåte

[Klikk her for å se oppgaveteksten.](issues_og_prosjekt)

### Tips til veiledere

- Oppgaven passer godt før et større prosjekt, for eksempel i [Fra idé til app
  med KI](../../fra_ide_til_app/planen/planen), der historiene i `PLAN.md` kan
  bli issues.

- Prosjekttavla kan også brukes av hele klassen, med én tavle per gruppe. Da ser
  du som lærer hvor hver gruppe står.

- GitHub endrer menyene sine av og til. Står ikke knappen der oppgaven sier,
  let etter samme ord i nærheten.

- I offentlige repoer kan alle lese issuene. Snakk om hva som ikke skal stå
  der, som personopplysninger og passord.

### Hva er testet

Oppgaven er skrevet i november 2026 ut fra github.com. Den er ikke prøvd med
elever ennå.
