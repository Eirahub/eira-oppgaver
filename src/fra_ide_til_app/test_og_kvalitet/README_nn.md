# Om oppgåva {.activity}

Eleven lagar ei testliste ut frå akseptansekriteria i `PLAN.md`, testar kantar
og feil, sjekkar universell utforming, får ein kodegjennomgang og lærer å teste
alt på nytt før kvar publisering.

## Oppgåva passar til: {.check}

__Fag__: Informasjonsteknologi, programmering

__Tilrådde trinn__: Vidaregåande

__Tema__: Testing, akseptansekriterium, kanttilfelle, universell utforming,
kodegjennomgang, regresjonstesting

__Tidsbruk__: 90 til 120 minutt

## Kompetansemål {.challenge}

- [ ] __Informasjonsteknologi 2__: vurdere og bruke strategier for feilsøking og
  testing av programkode

- [ ] __Informasjonsteknologi 2__: vurdere brukervennligheten i egne og andres
  programmer og foreslå forbedringer

- [ ] __Informasjonsteknologi 1__: planlegge og lage nettsider som tar hensyn
  til brukervennlighet og universell utforming

- [ ] __Informasjonsteknologi 1__: utforske, strukturere og kommentere
  programkode

## Forslag til vurderingskriterium {.challenge}

`TEST.md` har minst éin test per «Ferdig når» og fleire kanttilfelle, med
resultat. Eleven har retta feil testane fann, og kan forklare éi forbetring
frå kodegjennomgangen.

## Føresetnader og utstyr {.challenge}

- [ ] __Føresetnader__: [Bygg MVP-en](../bygg_mvp/bygg_mvp_nn).

- [ ] __Utstyr__: PC med VS Code, Git, nettlesar og ein KI-kodeassistent.
  Gjerne ein mobil.

### Tips til rettleiarar

- Les [Rettleiing for
  lærarar](../veiledning_for_laerere/veiledning_for_laerere_nn) om risiko,
  kontoar og ansvar i kurset før du startar.

- Oppgåva kan godt gjerast i par: éin byggjer, éin testar. Byt roller
  undervegs.

- Testen med `<b>hei</b>` er ein enkel inngang til tryggleik. Bruk han til å
  snakke om kvifor appen aldri skal stole på det brukaren skriv.

- `TEST.md` blir brukt igjen i Test med kundar og Etter lansering.

### Kva er testa

Oppgåva er skriven i november 2026 og er ikkje prøvd med elevar enno.
